# Vexx 2.1 Release Notes

**Vexx 2.1** is the standalone release that ports the newer neuro-symbolic code
engine (previously embedded in Maya250M as "Vexx 3.5") into the standalone
Vexx repository, with additional hardening and corrections. Maya250M is a
source of features, not a runtime dependency.

## Version alignment

- Python package version: `2.1.0` (`pyproject.toml`, `python/vexx/__init__.py`).
- Rust workspace version: `2.1.0` (`Cargo.toml`).
- Vexx 1.5 history is retained in `docs/1.5-release.md`.

## New capability: code-generation / research-verification engine

A separate modular subsystem under `python/vexx/code_engine/` plus `cas.py`,
`calibration.py`, `cache_protocol.py`, `rl/code_rewards.py`, and
`bridges/code_hf.py`:

- Incremental Python lexer (`LexerState`, `advance_lexer_state`) with PEP 701
  nested f-string support.
- Live callable contracts (`ParameterContract`, `CallableContract`, `check_call`,
  `build_contracts`, `header_contract_from_text`).
- Tier-0/Tier-1 vocab/logit masking (`VexxCodeController.mask_logits`,
  `filter_draft_tokens`) with ID validation, sparse-vocab support, and a typed
  `DeadEnd` when all candidates are masked.
- Safe symbolic CAS (`safe_sympy`, `crane_cas_evaluate`, `solve_linear_system`,
  `integrate_definite`, `modular_pow`) behind the optional `.[cas]` extra.
- Rational single-row conflict contractor (`contract_single_row`) with explicit
  relation direction and generic cache adapters.
- Statistical / dimensional / epistemic diagnostics (`verify_statistical_report`,
  `verify_epistemic_calibration`, `parse_unit_dimensions`) with corrected GRIM
  rounding intervals and Student-t handling.
- Isolated subprocess sandbox (`SandboxRunner`) with honest `network_isolated`
  reporting; never falls back to in-process `exec`.
- Multi-cell experiments (`ExperimentEpisode`) with bounded preambles.
- Candidate verification, empirical consensus selection (`select_candidate`),
  differential fuzzing (`fuzz_against_oracle`), RLVR rewards, and atomic DPO
  export.
- Hugging Face code logits processor (`VexxCodeLogitsProcessor`).

## Corrections over the Maya reference

- f-string quote handling no longer rejects valid nested string literals.
- Session-isolated symbol tables keyed by a collision-resistant digest.
- Tokenizer ID validation (no negative indexing, sparse vocab).
- CAS is optional and bounded; base `import vexx` works without SymPy/NumPy.
- GRIM compares against the rounding interval implied by printed precision.
- t-test uses real Student-t when available; z is two-sided only when declared.
- Cache rewind is behind a protocol; recurrent state fails closed.
- Sandbox never claims network isolation it cannot enforce.
- Speculative filtering is documented as syntax-only prefix filtering, not a
  parallel tree verifier.
- Consensus selection is documented as empirical consensus, not formal MBR.
- RLVR rewards are not claimed to be reward-hacking-proof.

## Principal-engineering audit pass (this release)

All items below are covered by `tests/test_audit_regressions_v21.py` (the regression
gate) plus the focused suites named in each bullet.

**Soundness / correctness (P0–P1)**

- `nano_solver`: `eq` is encoded as two inequalities sharing one tracker, so
  `x == 5` with `x <= 3` is `UNSAT` with the right core instead of a silent `SAT`.
- `proof/certificate.py`: native dict/list ordering survives canonicalisation, and
  a non-hex signature is `False` rather than an exception.
- `code_engine/lexer.py`: whitespace no longer resets the pending callee
  (`return helper(` masks as a call to `helper`), raw-string backslash parity,
  PEP 701 nested f-string fields, and literal-newline rejection in raw strings.
- `code_engine/masking.py`: safe builtins seed the callable table, `in_string`
  suppresses the forbidden-name rule inside string literals, and the draft-token
  filter uses the same single-token predicate as the full mask.
- `code_engine/policy.py`: `heapq` is importable again, while `format` /
  `format_map` / `vformat` / `get_field` / `get_value` / `Formatter` are blocked at
  the attribute, so `"{}".format(...)` aliases and `string.Formatter()` cannot be
  used to reach the interpreter.
- `interval.py` / `crates/vexx-core/src/interval.rs`: identical rejection of
  leading-zero and non-finite dead prefixes (`00`, `01.5`, `inf`, `NaN`), identical
  `exp` prefix spans, and an `AffineForm.mul` radius that no longer collapses.
- `calibration.py`: Voltage `V = M:1, L:2, T:-3, I:-1` (so `V == J/C`), exact
  two-sided t/z/chi² handling, and `INVALID_P` for `p ∉ (0, 1]`.
- `cartridges/quant.py`: `S = 0` / `K = 0` closed forms, correct deep-ITM put IV,
  discounted intrinsic in the upper bound.
- `cartridges/sql.py`: `exp.Paren` unwrapping, AST-based tenant check.
- `serve.py`: HTTPS upstreams, `ThreadingHTTPServer`, `null` bodies in monitor
  mode, and a `X-Vexx-Verification: deferred` header for streamed responses whose
  verdict arrives inside the final certificate event.
- `mcp.py`: taint is preserved through `split`/`partition`/`casefold`/padding and
  the rest of the string-method family; `safe_format` returns a plain `str` only
  when nothing is tainted.
- `rl/code_rewards.py`: policy failures are a negative reward, not a crash.

**Sandbox (`code_engine/sandbox.py`)**

- Kind-tagged result envelope (`json` / `literal` / `opaque_repr`), bounded repr
  (≤ 4096 chars) and a bounded child stdout buffer, so a runaway program reports
  `output_limit` instead of hanging or flooding the parent.
- rlimits are applied *and verified* with `getrlimit` before the probe runs;
  `limits_enforced` reports what was actually set.
- Network isolation is reported by comparing the child's `/proc/self/ns/net` inode
  with the parent's, never assumed.
- `run_batch` executes every test case in one child process with a per-case
  `SIGALRM`, and `verify_candidate` uses it, so a multi-case candidate no longer
  pays one interpreter start per case.

**Performance and scale (Phase C)**

- `python/vexx/simplex.py`: an incremental exact-rational general simplex with
  `push`/`pop`, infinitesimal strict bounds, model re-verification and unsat-core
  propagation. `VexxNanoSolver` uses it for systems above its 24-variable
  Fourier–Motzkin cap, so large schemas now get `SAT`/`UNSAT` instead of
  `UNKNOWN`. It is differentially tested against Fourier–Motzkin
  (`tests/test_simplex.py`); where the reference engine cannot reconstruct a
  strict witness, the simplex decides and the case is not counted as a
  cross-check.
- Code masking now classifies each vocabulary once (identity-keyed plan cache),
  memoises id validation, and replaces the per-token forbidden-name generator with
  a tuple `startswith`. Measured on a synthetic 32K BPE-like vocabulary: **→ 33 ms/token
  from ~99 ms/token** in the same process. That is still far from the native
  15 µs/token target, which needs the code lexer itself ported to Rust — the Rust
  crate ships the JSON masker only.
- `crates/vexx-core/src/pda.rs`: `first_byte_allowed` + `TokenClasses` +
  `candidates_classified` / `mask_classified` drop structurally impossible tokens
  before cloning the automaton, with an equivalence test against the full replay.

**Runtime bridges (Phase D)**

- `bridges/_dlpack.py`: CPU masks with a matching dtype are handed to torch through
  `torch.from_dlpack` (no copy); device or dtype changes perform exactly one
  `as_tensor` copy; without torch the NumPy array is returned untouched.
- `bridges/kv_checkpoint.py`: `VLLMCheckpointAdapter` (block tables → `free` on
  rewind) and `SGLangCheckpointAdapter` (`RadixCache.match_prefix` jump-forward),
  both duck-typed and loud (`UnsupportedHost`) when a host lacks the hooks. Tested
  against faithful fakes; **not** verified against live servers.

## Branding

Release is branded **Vexx 2.1**. `Vexx35Controller` / `Vexx3Controller`
identifiers are not primary API; at most deprecated aliases. Package and Rust
versions stay aligned at `2.1.0`.

## Known limits

- Rust/WASM acceleration is unchanged for existing JSON-mask semantics; the new
  code engine ships in pure Python first.
- Sandbox network isolation depends on the host OS/container; `network_isolated`
  is reported honestly per run.
- CAS CPU protection is via operation/size bounds, not an in-process timeout.
- Statistical diagnostics return `UNKNOWN` when evidence is insufficient.
- No benchmark numbers are claimed from unit tests.
- The incremental simplex is Python-only; the Rust solver still uses bounded
  Fourier–Motzkin above its cap.
- Phase D integration is tested against fake torch/vLLM/SGLang objects only: no
  GPU, vLLM or SGLang installation exists in the build environment, so live KV
  rewind and DLPack throughput are unverified.
- `seccomp` filtering is not implemented (no dependency-free syscall filter ships
  here); rlimits plus the namespace check are what the sandbox enforces.
## Second audit pass (November 2026)

A second end-to-end audit differentially fuzzed the pure-Python engine against the compiled
`vexx-py` extension (release build, 24k random prefixes, 20k numeric-prefix cases, 3k
generated documents) and reviewed the proxy, CAS and contractor surfaces. Every item below
had a failing reproduction before its fix; the regressions live in
`tests/test_audit_v22.py`.

**Correctness**

- **Dead number prefixes.** The incremental JSON automaton accepted `7.E`, `5.e` and
  `1.e5` — no completion of them is a number — so the masker could emit a token that
  `parse_json` then rejected. The step grammar now requires a fraction digit before an
  exponent.
- **Non-finite numbers.** Rust `Pda`/`VocabularyTrie` and Python `JSONPushdownAutomaton`
  accepted overflowing literals (`72E934`, `[90e9376]`, `1e400`) that the strict parser
  refuses. Both engines now reject an overflowing exponent once it can no longer be rescued;
  a long mantissa stays open because `9…9e-400` is finite.
- **Interval crashes.** `Interval.empty().sub(...)` and `inf - inf` raised `ValueError`
  from the endpoint constructor. Empty operands now short-circuit and indeterminate sums
  widen outward instead of crashing.
- **Numeric-prefix parity.** `\r` is JSON whitespace but was missing from the terminator
  set, so `"342\r"` became an open integer prefix (span up to 1e17) instead of the point
  342. A negative exponent can also underflow to `0.0` (`1e-` → `1e-999`); the prefix
  scanner treated that completion as dead.
- **Native contractor.** The Rust `revise_linear` skipped inequality narrowing, so it
  reported *feasible* for boxes Python refutes (`x >= 0` and `2x <= -1`). It now performs
  the same directional HC4 inverse (rest lower/upper sums), never the unsound full-interval
  division that would force `x >= 9` in `x + y <= 10, y in [0,1]`.
- **CAS symbolic exponent.** `safe_sympy("2**x")` raised `TypeError` from `int(Symbol)` in
  the intermediate-size guard. The guard now only converts integer exponents.
- **Proxy error handling.** `vexx serve` relabelled every upstream non-200 response whose
  body was JSON as 200 (hiding 429/500s), silently verified an unknown `vexx_spec` against
  the default schema, and read unbounded request bodies. It now passes upstream failures
  through with `X-Vexx-Verification: upstream-error`, answers `400 unknown_spec`, and
  rejects bodies above 16 MiB with 413.

**Performance**

- Native masking is now exact *and* fast: `VocabularyTrie.mask` is used as the preferred
  path (after `Pda` was fixed to agree with `prefix_status` on 24k prefixes), with the
  stateless `allowed_tokens` and the new `mask_exact` as fallbacks. On a synthetic 32K
  vocabulary (release build): **16.5 ms → 0.43 ms per mask**; a warm `TokenMasker`
  call drops from ~88 ms to ~3.4 ms.
- `TokenMasker` keeps its automaton across steps and feeds only the appended suffix. An
  8k-step generation over a 72 KB document now averages **0.08 ms/step**; re-parsing the
  final prefix alone costs ~181 ms, which is what every step used to pay.

**Remaining known differences**

- `canonical_document` renders an *integral float* literal without `.0`
  (`8E9` → `8000000000`), because `Json::Number` is an f64 with no int/float tag.
  Structure, strings and all non-integral numbers match `json.dumps` exactly.
- The Rust contract is intentionally a one-sided refuter: `feasible` is not a witness.
  Callers that need a decision use the Python simplex/solver.
